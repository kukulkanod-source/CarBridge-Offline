# Область приложения и панель — 0.32

Вместо наложения панели поверх стороннего приложения введена композиция двух дисплеев.

1. Scrcpy создаёт внешний дисплей по выбранному профилю, например 1920×1080 / 300 dpi. Только он кодируется и передаётся в ГУ как 1280×720.
2. HuContentPresentation содержит SurfaceView. DisplayManager создаёт для его Surface отдельный PUBLIC | OWN_CONTENT_ONLY дисплей приложения. Захват физического экрана не используется.
3. Постоянная панель: Surface и дисплей приложения получают высоту внешнего дисплея минус реальная высота панели. Полный экран: получают всю высоту, панель скрывается.
4. Приложения запускает shell `am start --display APP_ID`; команды ориентации и диагностика направлены в APP_ID. Домашняя сетка и элементы управления остаются во внешнем дисплее.
5. Ввод ГУ попадает в наружный дисплей, затем SurfaceView пересылает MotionEvent через отдельный control-only процесс scrcpy в APP_ID. Пальцы сохраняют свои id. Клавиша Назад направляется туда же; питание физической панели — через основной сервер.
6. При закрытии сессии освобождаются оба дисплея, Surface, каналы управления и процессы.

Ограничения: обычный виртуальный дисплей не гарантирует воспроизведение защищённого DRM-видео. Создание дисплея, ввод, поведение приложений и отсутствие системных декораций необходимо подтвердить на устройстве. Не подменять отказ создания окна незаметным наложением панели.

Документация Android: https://developer.android.com/reference/android/hardware/display/DisplayManager
Документация Presentation: https://developer.android.com/reference/android/app/Presentation
Формат управления и подключение: исходники Genymobile scrcpy DesktopConnection и Controller.
